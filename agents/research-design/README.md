# 디지털 수업 연구설계 에이전트 사용과 변경 사항

첫 번째 에이전트의 현행 지침은 이 폴더의 `AGENTS.md`다. 기존 연구설계·수업·평가·윤리 규칙을 바탕으로 추천과 계획서 작성을 중심으로 흐름을 바꿨다. 두 전문 역할 구조와 연구 산출물 경로는 유지한다.

## 이전 지침과의 차이

| 구분 | 이전 | 현행 |
| --- | --- | --- |
| 시작점 | 사용자 수업 아이디어 구체화 | 연구보고서 품질 기준과 여건을 고려한 후보 3개 추천 |
| 추천 형식 | 제목·목적·문제 등을 단계별 제안 | 연구문제·방법과 절차·수업 모델·기대 변화의 네 항목 |
| 주제 결정 | 구체화하며 설계 진행 | 사용자 선택 후 필요한 정보 질문 |
| 주 흐름 | 수업 설계·적용·결과보고서까지 | 연구설계·계획서 초안·논리와 근거 점검 |
| 초안 목차 | 결과보고서 Ⅰ~Ⅴ 중심 | 요청한 Ⅰ~Ⅳ 계획서 표준목차 |
| 결과 처리 | 계획 단계는 평가계획으로 대체 | Ⅳ 제목을 유지하고 기대 변화·검증 방법으로 작성 |
| 일반화 | 보고서 후반에 별도 작성 | 추천부터 검토하고 계획서 Ⅳ에 조건·활용 계획 포함 |
| 파일 출력 | 요청 시 Markdown 저장 | 계획서 요청 시 Markdown 먼저 작성하고 DOCX 별도 출력 |
| 문헌 검색 | 부족한 근거 표시 후 별도 역할 | 요청할 때만 검색, 본문 표시와 근거 공백·입력 경로 전달 |
| 원본·버전 | 날짜·주제 중심 파일명 | 버전별 저장, 문헌 확인 후 새 버전으로 반영 |

내용상 변경은 중간 정도다. 추천 화면과 작업 순서·출력 규칙을 바꾸는 것이 중심이며, 연구방법·수업 전략·윤리의 기본은 이어받았다. 구조상 변경은 첫 번째 에이전트 진입 경로와 공용 서식 추가 정도다.

## 두 에이전트의 연결

```text
사용자 → 루트 AGENTS.md
  → research-design: 추천 → 사용자 선택 → 설계 → Markdown·DOCX → 점검
  → 사용자가 문헌 작업 요청
  → literature-search: 정확한 계획서 경로 입력 → 검색·검증·PDF·근거 지도
  → 사용자가 본문 반영 요청
  → research-design: 확인된 근거를 새 버전으로 반영 → 재점검·DOCX 갱신
```

`outputs/research-proposal/`을 유지하므로 두 번째 에이전트의 지침을 고칠 필요가 없다. 문헌 작업 요청 시 최신 Markdown 경로를 명시해 두 번째 에이전트가 이전 `final/` 파일을 먼저 선택하는 일을 방지한다. 추천·점검·인계 문서는 `drafts/` 바깥에 두어 연구계획서와 혼동하지 않게 한다.

첫 번째 에이전트는 이 폴더의 지침과 서식을 사용한다. 좋은 연구보고서 작성이라는 표현을 사용하며, 기존 평가 기준과 배점·작업 절차·출력 규칙을 유지한다.

## 사용 예시

> projects/[연구명]에서 작업해줘. [학교급·학년·교과]의 [수업 문제]를 개선할 연구문제 3개를 추천해줘. 기기는 [여건], 적용 기간은 [기간]이야.

> 2번 연구문제로 결정할게. 필요한 내용을 질문한 뒤 연구설계, 표준목차 계획서 Markdown·DOCX, 논리와 근거 점검까지 해줘. 문헌 검색은 아직 하지 마.

> [계획서 Markdown 경로]의 근거 공백을 문헌 에이전트로 검색하고 공개 PDF를 확보해줘. 본문 반영은 하지 마.

현재 `projects/`에는 `_template`만 있으므로 실제 연구를 시작할 때 프로젝트 이름을 지정한다. 에이전트 설정 작성만을 위해 임의의 연구 프로젝트나 연구계획서·DOCX를 만들지 않는다.
